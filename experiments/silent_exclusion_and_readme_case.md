# 조용한 파일 제외와 README 대소문자

2026-09-14

## 발단

MSA 강의 레포(자바 + 파이썬 혼합)를 인덱싱했더니 파일 9개, 청크 52개가 나왔다.
숫자만 보면 정상 종료다. 실제 레포에는 360개 파일이 있었고 그중 9개만 분석됐다.
비율로 97.5%가 빠졌는데 CLI에도 웹 화면에도 아무 표시가 없었다.

사용자는 레포 전체가 분석된 줄 알고 면접 질문을 받는다.
부분 결과를 완전한 결과로 보이게 하는 것은 틀린 답을 내놓는 것보다 나쁘다.
틀린 답은 의심할 여지라도 주지만 이쪽은 의심할 단서가 없다.

## 무엇을 셀 것인가

수집에서 파일이 사라지는 자리는 두 곳이었다.
확장자가 대상이 아닌 경우와 크기 상한(500KB)을 넘는 경우다.
전자만 보고 있었는데 후자도 똑같이 조용했다.
후자가 더 위험하다. 사용자는 파이썬 레포를 넣었으니 파이썬은 다 들어갔다고 믿는다.

세 가지를 정했다.

**제외 디렉터리는 세지 않는다.**
`.venv`, `node_modules`는 진입 자체를 막으므로 자연히 안 세진다. 그대로 두기로 했다.
`node_modules에서 12,000개 제외` 같은 줄이 뜨면 정작 봐야 할 `.java 51`이 묻힌다.
보고 대상은 "사용자가 자기 코드라고 믿었는데 빠진 것"이지 의존성 폴더가 아니다.

**상위 몇 개만 보이고 나머지는 접는다.**
MSA 레포에서 28종이 한 줄로 쏟아졌다. 빌드 산출물인 `.class` 103개가 맨 앞이고
`.java` 51개가 그 뒤에 묻혔다. `.aa`, `.ab`, `.ac`(쪼갠 압축 조각), `.tar`, `.zip`은
사용자가 "내 코드인 줄 알았는데"라고 느낄 대상이 아니다.
상위 5종만 나열하고 나머지는 `그 외 23종 72개`로 접었다.
진입점과 모듈 지도에서 이미 같은 기준으로 접고 있어 규칙이 일관된다.

한 종류만 남을 때는 접지 않는다. `그 외 1종 1개`가 `.toml 1`보다 길고 정보는 적다.

**개수가 아니라 경로를 들고 있어야 한다.**
처음에는 확장자별 개수만 남기는 구조로 짰는데 틀렸다.
README와 pyproject.toml은 수집 대상이 아니면서 별도 경로로 인덱싱된다.
이것들을 보고에서 빼려면 뺄셈이 필요하고, 개수로는 뺄셈이 안 된다.
`CollectResult`가 경로 목록을 들고, 집계는 별도 함수에서 한다.

## 파생 발견: 대소문자를 구분하지 않는 파일시스템

보고에서 README를 빼는 처리를 넣고 나서 이상한 것을 봤다.
vibecheck 레포에서는 제외가 21 → 19로 정확히 둘(README.md, pyproject.toml) 줄었는데
MSA 레포에서는 숫자가 그대로였다. 같은 코드가 한쪽에서만 동작하고 있었다.

MSA 레포의 루트 README는 소문자 `readme.md`였다.
인덱스에 저장된 청크의 `file` 값은 `README.md`였다.
디스크에 없는 이름이 인덱스에 들어가 있었다.

원인은 `to_readme_chunks`의 구조였다.

```python
for name in README_NAMES:      # ("README.md", "readme.md", ...)
    path = Path(root) / name
    if path.is_file():
        break
```

macOS는 경로를 **조회**할 때 대소문자를 무시한다.
`README.md`로 조립한 경로가 `readme.md`를 연다. 그래서 첫 후보에서 바로 통과하고,
그 뒤로 `name`(후보 문자열)이 `file`, `symbol`, `code`에 전부 박힌다.

리눅스였다면 `README.md`는 없다고 나오고 두 번째 후보에서 정상적으로 잡혔을 것이다.
**macOS라서 생긴 버그다.**

같은 뿌리의 두 번째 자리가 `read_readme`에 있었다.

```python
for path in sorted(root.glob("README*")):
```

**glob은 패턴 매칭이라 대소문자를 구분한다.**
경로 조회에서만 관대하다는 것이 핵심이다. 같은 파일시스템에서 한쪽은 통과하고
한쪽은 실패하므로, "macOS는 대소문자를 무시한다"는 한 줄로 기억하면 반드시 틀린다.

`root.glob("README*")`는 `readme.md`가 있어도 빈 목록을 돌려준다.

## 영향

| 자리 | 증상 |
|---|---|
| `to_readme_chunks` | 제외 보고가 README를 제외됐다고 잘못 말함 (`.md 14`, 실제 13) |
| `to_readme_chunks` | 리눅스에서 `find_code_entries`가 파일을 열지 못함 — `except OSError`가 삼켜 조용히 진행 |
| `read_readme` | 요약 프롬프트 재료에서 README가 통째로 빠짐 |
| `read_readme` | 화면 하단이 "README 없음"으로 표시 |

세 번째가 가장 크다.
"이 프로젝트가 무엇인가"의 답은 코드에 없고 README에만 있다.
소문자 README를 쓰는 레포는 그 답의 유일한 재료 없이 요약이 만들어지고 있었다.

고친 뒤 같은 질문을 다시 던지자 답변 근거에 `readme.md` 절이 여섯 개 올라왔다.
자바 레포인데도 서비스 구성과 기술 스택까지 정확히 설명했다.

## 수정

양쪽 다 디렉터리를 훑어 실제 이름을 얻는 방식으로 바꿨다.
후보 목록의 우선순위는 유지하되 대조는 소문자로 눕혀서 한다.

```python
actual = {p.name.lower(): p for p in Path(root).iterdir() if p.is_file()}
for candidate in README_NAMES:
    path = actual.get(candidate.lower())
    if path is not None:
        break
```

## 확인

`.md 14 → 13`, 전체 `349 → 348`, 재인덱싱에서 `오래된 청크 11개 삭제`.
청크 id가 `README.md#...`에서 `readme.md#...`로 바뀌어 `VectorStore.prune`이
옛 id를 걷어냈다.

vibecheck 레포는 실제 파일이 대문자라 아무것도 바뀌지 않았다. 이것도 확인 대상이었다.

## 남긴 한계

**모노레포에서 로컬 패키지가 외부 의존성으로 잡힌다.**
`recommend-service/app/`이 `app`이라는 서드파티 라이브러리로 분류된다.
내부 모듈 이름 집합을 레포 루트 기준으로 만들기 때문이다.

화면의 태그로 끝나지 않는다는 것을 이번에 알았다.
`interview`가 만든 질문이 이렇게 나온다.

> 외부 라이브러리로 `app`, `fastapi`, `httpx`, ... 를 씁니다. 각각 어디에 쓰이나요?

사용자가 답해야 할 질문에 로컬 패키지가 섞여 들어간다.
모노레포 사용자는 이 질문에 답할 수 없다.
구조 변경이 필요해 미루고 README에 명시했다.

**README 처리가 두 곳에서 범위가 다르다.**
`read_readme`는 `readme`로 시작하면 다 읽는데(`.rst` 포함),
`to_readme_chunks`는 `.md`/`.markdown` 네 이름만 받는다.
`README.rst`인 레포는 화면이 "README 있음"이라 하면서 청크는 없고
제외 목록에 `.rst 1`이 뜨는 모순이 생긴다.
절을 나누는 규칙이 마크다운 헤딩에 기대고 있어 `.rst`를 지원하려면 파서가 따로 필요하다.

**상위 디렉터리를 가리키는 심볼릭 링크에서 수집이 멈추지 않는다.**
`entry.is_dir()`가 링크를 따라간다. 실제로 만난 적은 없다.

## 배운 것

대소문자를 구분하지 않는 파일시스템은 **경로 조회에서만** 관대하다.
glob, 문자열 비교, 저장된 이름의 대조는 전부 구분한다.
"존재를 확인했으니 이 이름이 맞다"가 성립하지 않는다.
확인에 쓴 이름과 디스크의 이름은 다를 수 있고, 그 차이는 예외 없이 진행된다.

같은 개념을 다루는 코드가 두 곳에 있으면 규칙도 두 벌이 된다.
README를 찾는 일이 `chunker`와 `overview`에 각각 있었고 방식도 범위도 달랐다.
한쪽을 고치는 동안 다른 쪽은 계속 틀린 채로 있었다.
