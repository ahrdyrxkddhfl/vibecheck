# 식별자 검색이 벡터로는 안 된다

측정일: 2026-08-28
대상: vibecheck 자기 자신 (청크 197개, top_k 기본 8)
코드 변경 없음. 인덱스를 읽기만 했다.

## 발단

`whyd practice` Q2에서 근거 8개에 `cli.py::main`이 없었다.
진입점을 묻는 질문에 진입점 함수가 안 온 것이다.

## 측정 1 — main이 몇 등인가

질의 `콘솔 스크립트 진입점`. 이 문장은 `main`의 독스트링 그대로다.

- `main` **69등**, 거리 0.8629 (1등 0.6814)
- 청크는 인덱스에 정상 존재. 청킹 문제가 아니다.

임베딩 텍스트를 조각내 각각 질의와의 거리를 쟀다.

| 조각 | 거리 |
|---|---|
| 전체 (지금 방식) | 0.8629 |
| 머리말 뺌 (요약+코드) | 0.8549 |
| 요약만 | 0.8206 |
| 코드만 | 0.8612 |
| 머리말만 | 0.7770 |

최선이 0.7770으로 1등 0.6814에 못 미친다.
**`build_embedding_text`를 어떻게 조합해도 이 청크는 상위에 못 온다.**

"코드만"이 0.8612인 것이 핵심이다. 코드 안에 질의 문장이 글자 그대로
들어 있는데도 가까워지지 않는다.

## 측정 2 — 식별자로 확인

질의 `child_by_field_name`. tree-sitter API로 `parser.py`에서만 쓴다.
이 낱말을 code에 담은 청크 6개의 순위:

| 순위 | 청크 |
|---|---|
| 4 | `vector.py::build_embedding_text` |
| 18 | `parser.py::walk` |
| 35 | `parser.py::extract_imports` |
| 118 | `parser.py` (파일 청크) |
| 126 | `parser.py::extract_imports.scan` |
| 133 | `vector.py` (파일 청크) |

**`top_k=8` 안에 실제 사용처가 하나도 없다.**
4등은 사용처가 아니라 독스트링에 예시로 이름을 적어둔 자리다.
문장 속 언급이 실제 사용처를 이겼다.

## 결론

`build_embedding_text` 독스트링에 적힌 근거가 사실이 아니다.

> 'child_by_field_name 쓰는 데 어디야?' 같은 식별자 질문은 코드 원문이 받아낸다.

코드 원문을 넣어도 식별자 질문을 받아내지 못한다.
`paraphrase-multilingual-MiniLM-L12-v2`는 문장 뜻을 재는 모델이라
희귀 식별자를 하나의 단위로 보지 않는다. 모델을 바꿔도 정도의 문제다.

대신 코드 원문은 청크마다 `def`, `self`, `return`이 반복되는 텍스트를
넣어 벡터를 서로 닮게 만든다. 상위 5개 거리가 0.68~0.75에 몰려 있다.

**검색에 경로가 하나 더 필요하다.** 식별자는 문자열로 찾고 자연어는
벡터로 찾아 합친다. 채점 검색을 질문·답변 합집합으로 바꾼 것과 구조가 같다.

## 다음

측정 세트를 먼저 고정한다. 식별자 질문 몇 개와 각각의 정답 청크를
정해 지금 순위를 기록해두지 않으면, 고친 뒤 나아졌는지 말할 수 없다.
